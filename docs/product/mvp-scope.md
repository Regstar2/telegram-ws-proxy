# MVP scope

## Пользователь

Пользователь Android, которому нужен обычный Telegram-клиент с автоматически встроенным локальным TgWsProxy transport без установки и ручного запуска второго APK.

## Проблема

Текущий `tg-ws-proxy-android` работает отдельным приложением: пользователь запускает локальный proxy service и затем применяет его в Telegram. Это добавляет отдельный lifecycle, отдельный UI и дополнительный шаг настройки.

Нужно проверить, можно ли убрать этот UX-слой, не превращая проект в глубокий форк Telegram.

## Core scenario

1. Репозиторий получает точный upstream Telegram из `DrKLO/Telegram`.
2. Минимальный integration layer подключает переиспользуемый TgWsProxy runtime.
3. Telegram запускает runtime внутри своего процесса/приложения.
4. Telegram использует штатный proxy API для соединения с `127.0.0.1:<port>`.
5. Runtime маршрутизирует трафик через поддерживаемый WebSocket/Cloudflare route.
6. Пользователь может подключиться к Telegram и выполнить базовый обмен сообщениями без отдельного TgWsProxy APK.

## Обязательно (P0)

- воспроизводимо получать зафиксированный upstream Telegram;
- не изменять `TMessagesProj/jni/tgnet/`;
- выделить reusable runtime из `tg-ws-proxy-android` либо эквивалентный минимальный core package;
- реализовать маленький Telegram-specific adapter;
- собрать ARM64 debug/prototype APK;
- проверить запуск, подключение, отправку и получение сообщения;
- проверить reconnect после перезапуска приложения;
- измерить собственный diff относительно upstream;
- до публичного распространения закрыть лицензионный blocker Telegram GPL v2 ↔ TgWsProxy GPL v3.

## Не входит

- изменение Telegram networking/tgnet;
- дополнительные функции Telegram;
- полноценный отдельный proxy UI;
- автоматический release на каждый upstream commit;
- store publishing;
- auto-update приложения;
- несколько ABI;
- расширенная диагностика;
- полная локализация;
- глубокий ребрендинг;
- поддержка desktop/iOS.

## Публикация

Первый результат — локальный Prototype APK и воспроизводимые build-инструкции.

Публичный GitHub prerelease допустим только после решения лицензионного вопроса и выполнения базового smoke test.

## Критерий успеха

Prototype считается успешным, если одновременно выполнено:

- Telegram работает через встроенный TgWsProxy без второго APK;
- `tgnet` остаётся без изменений;
- основной Telegram-specific diff укладывается ориентировочно в 1–5 upstream-файлов;
- интеграция отделена от reusable runtime;
- переход на следующий совместимый upstream commit не требует переписывания архитектуры.
